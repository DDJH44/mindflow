# MindFlow 前端设计规范

> 状态：设计语言基线 · 2026-10-11
> 适配对象：`web/`（Vue 3 + TypeScript + Vite，**无 UI 组件库**，手写 CSS）
> 相关文档：`MIND_FLOW_PLAN.md` §31（体验规划与已知问题）

## 0. 这份文档主张什么

大多数"AI 产品界面"长得像同一个模板，而这种相似**不是审美问题，
是一组可枚举的具体选择**。因此"去 AI 味"可以不靠品味、靠清单：

> **本文档的每一节都同时说明"做什么"和"不做什么"。**
> 后半部分的排除清单（§9）与正文章节同等重要 ——
> 它把"别做成那样"变成了可逐条核对的规则。

同时有一条更根本的原则贯穿全文：

> **界面不得承诺系统做不到的事。**
> （来源：缺陷 D55 —— 界面上写着支持 PDF/DOCX，而后端当时只认
> TXT/MD，用户上传简历直接失败，错误信息却指向"文件类型不支持"，
> 看起来像用户的文件有问题。）

### 0.1 现状与目标的区别（读本文档前必看）

写这份文档时我犯过一个错误，值得留在这里：

> 第一版把 `--font-mono` / `--fs-*` / `--sp-*` 等令牌写成了
> **已经存在**的样子，而实际上它们当时一个都不存在 ——
> 只有 18 个颜色令牌是真的。同时文档声称"字号只有六档"，
> 而 CSS 里实际散落着 **8 档**。

一份描述不存在之物的规范是没法执行的。因此现在：

**已落地的（可以直接用）：**

| 类别 | 令牌 |
| --- | --- |
| 颜色 | `--bg` / `--surface` / `--surface-sunk` / `--border` / `--border-strong` / `--text` 三级 / `--ink` / `--ink-soft` / `--accent` 三档 / 四个语义色及 `-soft` |
| 字族 | `--font-sans` / `--font-mono` |
| 字号 | `--fs-xs` ~ `--fs-2xl` / `--fs-hero`（八档，见 §3.2）|
| 间距 | `--sp-1` ~ `--sp-7` |
| 宽度 | `--w-page` / `--w-wide` / `--w-read` |
| 动效 | `--dur-fast` / `--dur-base` / `--ease` |
| 形状 | `--radius-sm` / `--radius` / `--radius-pill` |

**尚未收敛的（已知不一致）：**

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 字号 | ~~CSS 里仍有 16/20/24/26px 四处不在阶梯内~~ | ✅ **已收敛（2026-10-12）** |
| 间距 | 仍有非 4 倍数的值（如 `padding: 10px 15px`）| 收敛到 `--sp-*` |
| 组件 | 已抽出 `PageState`（§11.5）与 `BrandMark`；其余重复结构尚未评估 | 按"逐字重复"判据评估，不做无收益抽取 |
| 列表/表格的分隔线 | 部分仍是 `--border`，部分已换 `--border-strong` | 统一规则：**行分隔用 `--border`，表头用 `--border-strong`** |

### 0.2 字号收敛的做法（可复用的方法）

四处游离值与 19 处硬编码**都只在源码里看**，而在浏览器里
可能因为三个原因与预期不符，**且都不报错**：

1. **令牌未定义** —— 拼错 `var(--fs-xxl)` 会**静默回退**到继承值
2. **更具体的选择器覆盖** —— `.page-head h1 { font-size: … }`
   会盖掉 `h1`，而 grep `h1` 只看到一处
3. **相对单位残留** —— 若有 `1.1em`，它随父级变化，
   "收敛到令牌"的假设就破了

因此收敛时配了 `app/core/check_computed_fonts.py`：
在**真实浏览器**里读 `getComputedStyle`，断言
七个令牌的解析值、关键元素的计算字号，以及
**所有渲染元素**的字号都落在阶梯内。

> ⚠️ 那个检查的第一版把 `<html>` / `<head>` / `<title>` 也算进去，
> 于是每次都误报一个 16px —— 那是**浏览器默认样式**，不是我们写的。
> 判据必须限定在"我们控制其排版的元素"上。

把这些写清楚，是为了让人知道**哪些能直接依赖、哪些还在路上** ——
而不是让下一个人（或 AI）以为一执行就会得到一致的界面。

### 0.3 视觉审查：先截图，再改

**这是 2026-10-15 那次修订里最有用的方法。**

起因是用户的一句话："界面别扭 不太好看"。而这类反馈**不能靠读代码处理** ——
CSS 令牌的值是抽象的，"好不好看"是渲染之后的事。

于是加了 `app/core/capture_screens.py`：用 Playwright
登录后逐页**截整页图**，并打印每页的**计算样式分布**
（字号分布、背景色分布、圆角分布）。

**它抓到了三个只有看截图才能发现的问题：**

| 问题 | 为什么读代码发现不了 |
| --- | --- |
| **界面上有 3 个同名空项目** | 那是我自己早期测量脚本留下的垃圾。代码没问题，**是数据污染** |
| 登录页深色底**没铺满**（四周白边） | 登录页被套在 `.content`（`max-width` + padding）里。CSS 完全正确，但组合结果错 |
| **当前选中的筛选项反而最模糊** | 选中态是用 `:disabled` 表达的，命中了 `opacity: .5` |

这三个的共同点：**每一处单独看都"没有 bug"**。
它们只在真实渲染 + 真实数据下才出现。

> ⚠️ 这与 D66（登录页永远显示"正在加载…"）是同一类。
> 那一次是**用户自己截图报告**的，而当时的走查与
> `check_computed_fonts` 都没发现。教训是：
> **"有没有渲染出来"和"渲染得对不对"是两件事，
> 后者必须用眼睛看。**

**可复用的做法**：

```bash
uv run python -m app.core.capture_screens
# 产物：web/screenshots/*.png（已 gitignore）
```

每次改视觉都跑一次，**改前改后各截一张对比**。
不要凭代码里的描述判断"已经好看了"。

### 0.4 规范与实现的"第二真相"

`check_computed_fonts.py` 里硬编码了一份期望值（`EXPECTED`），
看起来与 `app.css` 重复 —— 但**这个冗余是刻意的**：

> 若期望值也从 CSS 解析，这个检查就只是在验证"CSS 等于 CSS"，
> 恒真，永远通过。

它的价值正在于**它是一份独立的断言**。2026-10-15 改字号阶梯时，
它报了 **16 项失败** —— 那正是它该做的事。

因此规则是：**改阶梯必须同时改这两处**，
而"两处不一致"本身就是需要被发现的信号。

## 1. 设计方向

**三个词：克制、精确、工程感。**

它是一份工具，不是一份作品集。用户来这里是为了准备好面试，
不是为了欣赏界面。

> **2026-10-15 修订：从「安全的克制」改为「有主张的克制」**
>
> 原文的方向本身没错，但**执行出来是没有辨识度的** ——
> 用户的原话是"界面别扭 不太好看"。
>
> 问题不在"不够花哨"，而在**没有一个可被记住的决定**：
> 那个 `#3b6fe0` 蓝是任何 SaaS 都会选的默认值，
> 全站靠卡片边框分隔，视觉上没有焦点。
>
> 修订后的主张：**用排版做骨架，用一个有语义的强调色做点睛。**
> 仍然拒绝一切装饰性手段（§9 的排除清单**一条都没有放宽**），
> 但不再假装"没有决定"是一种决定。

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 密度 | **分区密度**：列表/表格紧凑，页面留白加大 | 靠**对比**制造节奏，而不是全站一个密度（原为"整体偏紧凑"）|
| 对比 | **靠层次 + 有意识的细线** | 从"尽量不画线"改为"画得准"：用 1px 极淡线分区，而不是给每个块加边框 |
| 圆角 | **小**（6/8px），不用大圆角 | 大圆角是"AI 味"最强的单一特征（§9.3）—— **不放宽** |
| 阴影 | **不用**，用背景分层 | 阴影多了界面会"飘"，也显得廉价 —— **不放宽** |
| 动效 | **只用于传达状态变化** | 不做装饰性动画 —— **不放宽** |
| 色彩 | **石墨黑做结构 + 琥珀橙表示"当前/进行中"** | 见 §2.2 |
| 字体 | 系统字族，**靠字号与字重做差异** | 不引入 Web 字体（§3.1 理由不变）|
| 排版 | **八档字号**，含一个大号等宽数字档 | 大号数字是**视觉锚点**，报告页的主角是分数 |

### 1.1 突破旧规则的三条，及理由

修订前的规范禁止或未涉及以下三件事。**突破是有意的，理由写在下面** ——
否则规范会退化成"以前说的话不算数"。

| 突破 | 旧规则 | 新规则与理由 |
| --- | --- | --- |
| **① 允许有结构的深色** | 全站浅底 | 深色**只用于两处**：顶栏、以及"进行中"这类需要强提示的状态条。**正文阅读区永远是浅底** —— 面试要长时间阅读，深色底会降低可读性（§9.1 反对的是"深色底 + 霓虹色"，不是反对深色本身）|
| **② 品牌色拆成两个职责** | "品牌色只用于主要动作与当前选中"，且只有一个主色 | 拆成 `--ink`（结构色，承载文字与深色区）与 `--accent`（琥珀橙，**只表示"当前/进行中"**）。**数量仍是两个，不是"到处点缀"**；橙色出现超过三处同样算错 |
| **③ 字号从六档到八档** | "只有六档" | 新增 `--fs-2xl`（页面标题）与 `--fs-hero`（44px，关键数字）。旧规则的本意是**防止随手加档**；这里新增的两档各有独立语义（页面级标题、视觉锚点数字），符合原规则"判据是'这个值有没有独立语义'" |

**没有放宽的**：不用渐变、不用毛玻璃、不用彩色光晕、
不用大圆角、不用阴影、不用 Emoji、不做装饰性动画、
不用 Web 字体。**§9 整节保持生效。**

## 2. 颜色

### 2.1 令牌（2026-10-15 修订）

```css
/* ---------------- 层次：三层底 + 一条极淡的线 ---------------- */
--bg:            #f4f5f7;   /* 页面底 */
--surface:       #ffffff;   /* 卡片 / 阅读区 */
--surface-sunk:  #fafbfc;   /* 下沉区（表格斑马、代码块底）*/
--border:        #e6e8ec;   /* 极淡：只用来分区，不用来"框住"内容 */
--border-strong: #d5d8de;   /* 需要明确可点的边界（输入框、次按钮）*/

/* ---------------- 文本三级 ---------------- */
--text:          #14171c;   /* 正文与标题（比旧值更深，提升对比）*/
--text-dim:      #5b6270;
--text-faint:    #8d94a1;

/* ---------------- 结构色：石墨黑 ---------------- */
/* 承载"结构"：顶栏底、深色状态条、以及最深一级文字。
   **它不是"另一个品牌色"**，而是一个接近黑的中性色 ——
   用它比纯黑柔和，比灰色有分量。 */
--ink:           #12151a;
--ink-soft:      #1c2027;

/* ---------------- 强调色：琥珀橙 ---------------- */
/* **只表示"当前 / 进行中"。** 这是全站唯一允许的彩色强调。
   选橙而非蓝的理由：蓝色是任何 SaaS 的默认值，没有辨识度；
   橙色在深色底上极亮、在浅底上也不刺眼，且天然带"正在进行"的语义。 */
--accent:        #d9600f;
--accent-hover:  #b9500b;
--accent-soft:   #fdf1e7;
--accent-text:   #ffffff;

/* ---------------- 语义色 ---------------- */
/* 语义色独立于强调色：**不要用强调色表示成功/失败** ——
   那会让"橙色"同时意味着"进行中"和"出错了"。 */
--ok:            #16794a;   --ok-soft:      #e8f6ef;
--warn:          #97620f;   --warn-soft:    #fdf5e4;
--danger:        #b3261e;   --danger-soft:  #fdecea;
```

### 2.2 使用规则（修订）

**① `--ink` 只出现在三处：顶栏、深色状态条、最深一级文字。**

不用于按钮底色（除"主要动作"），不用作大面积装饰。

**② `--accent` 只表示"当前 / 进行中"。一个页面上超过三处就算错。**

具体允许的场景：

| ✅ 允许 | ❌ 不允许 |
| --- | --- |
| 当前选中的项目、当前页导航 | 装饰性色块、分隔线 |
| "进行中"的状态标签与进度条 | 成功/失败状态（用 `--ok` / `--danger`）|
| 主要动作按钮（开始面试、提交回答）| 次要按钮、链接（用 `--text` 下划线）|

**③ 语义色与强调色不混用。**

`--accent` 说"正在发生"，`--ok` 说"完成了"，`--danger` 说"出错了"。
混用会让颜色失去含义 —— 而颜色是本规范唯一的"装饰"。

**④ `-soft` 变体只用于"区域底色"，且必须是状态区。**

反例（已修正）：长等待提示最初用了主色浅底。
主色在别处表示"可操作"，于是那个**纯状态区**看起来像能点。

**⑤ 不用渐变。**

渐变（尤其紫蓝渐变）是"AI 味"最强的特征之一（§9.1）。
纯色足够表达一切，而且打印、截图、深色模式下都稳定。

**⑥ 深色区上不用浅色文字之外的任何技巧。**

不用发光、不用半透明、不用模糊。深色带就只是一条深色带。

**⑦ 语义色不混用。**

"成功绿"只表示成功，"警告黄"只表示需要注意，
`--accent` 只表示"进行中"。
不要用绿色做装饰、不要用黄色表示"稍微重要"、
不要用橙色表示"出错了"。

### 2.3 深色模式

**暂不实现，但所有颜色已经走令牌**，因此将来只需覆盖
`:root` 的一组变量，不必改组件。

**前提条件**：新增任何颜色**必须**先加令牌。硬编码色值
（`color: #333`）会让深色模式变成一次全局搜索替换 ——
那种改动必然漏掉几处。

## 3. 字体与排版

### 3.1 字族

```css
/*
  保持系统字族：零加载成本、渲染最快。
  这是一份工具，用户不需要"设计过的字体"。
*/
--font-sans: -apple-system, BlinkMacSystemFont, 'Segoe UI',
             'PingFang SC', 'Microsoft YaHei', sans-serif;

/*
  等宽：用于**数字与代码**，不用于装饰。
  面试页的向量维度、字符数、耗时、代码片段都走它 ——
  等宽让数字对齐，而比例字体下"1024"和"1111"宽度不同，
  一列数字会跳。
*/
--font-mono: 'SF Mono', 'Cascadia Code', Consolas, monospace;
```

> **不要引入 Web 字体。** 中文 Web 字体动辄数 MB，
> 而收益是"看起来特别" —— 那正是本规范要避免的方向。

### 3.2 字号阶梯（2026-10-15 修订：六档 → 八档）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--fs-xs` | 12px | 元信息、标签、表格表头 |
| `--fs-sm` | 13px | 辅助说明、次要按钮 |
| `--fs-base` | 14px | **正文默认** |
| `--fs-md` | 15px | 题目正文（面试页的核心内容）|
| `--fs-lg` | 17px | 卡片标题 |
| `--fs-xl` | 21px | 区块标题 |
| `--fs-2xl` | **28px** | **页面标题**（新增）|
| `--fs-hero` | **44px** | **关键数字**（新增）|

**为什么允许从六档到八档**

旧规则的本意是**防止随手加档** —— 一旦有第七档，
就会有人加第八档。这个担忧是对的，但判据不是"数量"，
而是原文自己写的那句：

> 判据是"这个值有没有独立语义"，而不是"数量越少越好"。

新增两档各有独立语义：

- `--fs-2xl`（28px）：**页面级**标题。旧阶梯最高只有 22px，
  而页面标题与卡片标题（18px）只差 4px —— 视觉上几乎同级，
  这就是"界面没有焦点"的直接原因之一。
- `--fs-hero`（44px）：**关键数字**（额度、总分、维度中位）。
  报告页的主角是分数，不是标题。旧值 26px 不足以成为锚点。

**仍然禁止**随手写 `font-size: 16px`。八档是**上限**，
不是"以后可以加第九档"。

> ⚠️ 收敛现状：CSS 里目前仍有**少量游离值**（16/20/24/26px）。
> 修正时的规则是**映射到最接近的一档**，
> 而不是把这些值也加进阶梯 —— 后者只是把不一致制度化。

### 3.3 行高与字重

- 行高：正文 `1.6`，标题 `1.35`，**代码 `1.5`**
- 字重：**只用 400 与 600**。
  不用 500 —— 中文在 500 下渲染差异极小，
  却会让"次要强调"和"确定强调"无法区分。

### 3.4 数字必须用等宽

```css
.num { font-family: var(--font-mono); font-variant-numeric: tabular-nums; }
```

适用：分数、题号、耗时、计数、维度数。
**理由**：进度从 `9/10` 变成 `10/10` 时，比例字体会让整行跳动。

## 4. 空间与布局

### 4.1 间距

**只用 4 的倍数**：`4 / 8 / 12 / 16 / 24 / 32`（已写进 `:root` 为 `--sp-1` ~ `--sp-6`）。

**不要出现 `padding: 10px 15px`。** 那说明间距是随手调的。
> 现状：CSS 里仍有这类值，见 §0.1 的"尚未收敛"。

### 4.2 容器宽度

```css
--w-page:  960px;   /* 页面主内容 */
--w-read:  720px;   /* 长文本（面试题目、报告正文）*/
```

面试题目**按 `--w-read` 约束**：一行超过约 40 个汉字之后，
阅读时的回行定位会变难。这条不是审美，是阅读效率。

### 4.3 布局规则

**① 不居中一切。**

AI 生成界面最常见的症状是"所有东西居中"。
本项目里：**表单与正文左对齐；只有空状态和错误页居中。**

**② 不用等宽卡片网格。**

三张一样的卡片并排（"功能一 / 功能二 / 功能三"）是营销页的排版，
不是工具的。信息量不同就用不同的宽度和高度 —— **不对称是诚实**。

**③ 留白要"有用"，不是"高级"。**

大留白让界面看起来高级，但面试页要同时呈现题目、依据、
进度、历史问答。留白过大会逼着用户滚动。

---

## 5. 形状

```css
--radius-sm: 6px;    /* 按钮、输入框、标签 */
--radius:    8px;    /* 卡片 */
--radius-pill: 999px; /* 仅用于状态标签（tag）*/
```

**只有三档，且都很小。**

- **不用 16px 以上的圆角** —— 那是 §9.3 列出的首要特征
- **不混用**：同一个页面里不要既有 8px 又有 12px 的卡片
- `--radius-pill` **只给 tag**：胶囊形状用于标签是功能性的
  （表示"这是一个状态，不是一个按钮"），不是装饰

---

## 6. 图标

**当前的明确决定：不用图标库，用文字。**

```html
<!-- 对 -->
<button>暂停</button>
<button>结束并生成报告</button>

<!-- 错 -->
<button>⏸ 暂停</button>
<button>🎯 结束并生成报告</button>
```

**理由：**

1. **Emoji 是"AI 味"的首要特征之一**（§9.2）。
   而且它跨平台渲染不一致 —— 同一个界面在 Windows 和 macOS 上
   看起来像两个人做的。
2. **图标库为了三个图标引入一份依赖不划算。**
   项目里只有 7 个页面，用文字表达完全够。
3. **中文动词足够短。** "暂停"两个字，"结束并生成报告"七个字 ——
   不需要图标来节省空间。

**唯一例外**：纯装饰性的视觉元素（如进度流动条）不算图标。

**若将来确实需要图标**（例如工具栏密度要求高）：
选**单色线性图标**，统一 1.5px 描边，尺寸归入 4.4 的间距体系，
不用彩色图标。

## 7. 动效

### 7.1 唯一原则

> **动效只用于传达"状态发生了变化"，不用于装饰。**

一个动画如果不能回答"现在发生了什么"，就不要加。

### 7.2 时长与缓动

```css
--dur-fast:  120ms;   /* 悬停、聚焦 —— 快到几乎无感 */
--dur-base:  200ms;   /* 状态切换 */
--ease:      cubic-bezier(0.2, 0, 0.2, 1);
```

**不做超过 400ms 的动画。** 用户是来答题的，不是来看动画的。

### 7.3 已实现的正确范例：不确定进度条

长等待提示里的进度条**来回流动**，而不是按百分比填充：

```css
@keyframes waiting-slide {
  0%   { transform: translateX(-100%); }
  100% { transform: translateX(385%); }
}
```

**为什么是流动而不是百分比**：服务端分几个阶段
（保存回答 → 分析 → 生成追问），但**浏览器拿不到"正在哪一步"** ——
那些状态转移用 `commit=False`、在请求末尾才一次提交，期间查库看不到。

一个假的百分比会让人以为系统在精确汇报，而**一旦它停住，
用户的怀疑会比没有进度条时更强**。流动只声称"仍在进行"，
那是事实。

> 这条经历值得记住：我第一版把阶段做成"逐条打勾"来模拟进度，
> 截图复核时发现它在 32 秒时就显示"正在准备下一个问题" ——
> 而那时模型多半还在分析。**那是把估算当成了事实。**

### 7.4 必须尊重"减少动效"偏好

```css
@media (prefers-reduced-motion: reduce) {
  .waiting-track-fill {
    animation: none;
    width: 100%;
    opacity: 0.5;
  }
}
```

流动动画对前庭敏感的人不友好，而这里的信息在静态下也完整。

### 7.5 不做

- 入场/离场动画（列表项一个个淡入）
- 视差滚动
- 按钮点击的弹跳
- 数字滚动的动画

## 8. 状态设计

**每个需要与后端交互的界面，必须完整设计五种状态。**
漏掉任何一种，用户就会在那种情况下不知道发生了什么。

| 状态 | 要求 | 反面教材 |
| --- | --- | --- |
| **加载** | 骨架屏或明确的文字，**不是空白** | 白屏 |
| **空** | 说清"为什么空"和"怎么让它不空" | 只写"暂无数据" |
| **有数据** | 正常渲染 | — |
| **等待中** | 见 §8.2 | 一个转圈配"请稍候" |
| **失败** | 见 §8.3 | 裸 `Internal Server Error` |

### 8.1 空状态必须可行动

```html
<!-- 对：说明原因 + 给出下一步 -->
<p>还没有资料。上传简历和岗位 JD 之后，
   面试提问才能引用你的真实经历。</p>
<button>上传资料</button>

<!-- 错 -->
<p>暂无数据</p>
```

### 8.2 等待必须可见

**按耗时区分两种等待，给不同反馈：**

| 耗时 | 反馈 |
| --- | --- |
| < 1s | 不加提示（闪烁比等待更烦）|
| 1–5s | 按钮内转圈 + 禁用 |
| **> 5s** | **独立的等待区**：实时秒数 + 这一步要做什么 + 超时安抚 |

实测数据决定了这个分界：单轮答题耗时 **4.9s ~ 60.8s**
（21 次请求，均值 23s）。因此面试页的两处提交都走第三种。

### 8.3 失败必须可行动

错误信息要回答三个问题：**发生了什么、为什么、现在能做什么。**

```text
<!-- 对 -->
调用模型失败（APITimeoutError）。这是上游模型服务的临时问题，
本次回答已保存，可以稍后继续。

<!-- 错 1：裸异常 -->
Internal Server Error

<!-- 错 2：说不该说的话（D61 实际发生过） -->
调用模型失败。本次操作没有写入任何数据。
```

第二条错在哪：**那句话是假的** —— 会话确实被创建了、也经历了
状态转移。它让人以为什么都没发生，从而不去检查额度。

**规则：错误文案里每一句关于"系统做了什么"的陈述都必须是真的。**

## 9. 排除清单（"AI 味"的可枚举特征）

> **这一节与正文章节同等重要。** 它是可以逐条核对的规则，
> 而不是一句"要有品味"。

### 9.1 颜色与材质

| ❌ 不要 | 为什么 |
| --- | --- |
| 紫蓝渐变（`#6366f1` → `#a855f7`）| 2023 年后 AI 产品的默认配色，已成模板 |
| 毛玻璃（`backdrop-filter: blur`）| 降低可读性，且是"科技感"的廉价替代品 |
| 彩色光晕 / 发光边框 | 同上 |
| 深色底 + 霓虹色 | 开发工具风，但面试场景需要长时间阅读 |
| 半透明叠层 | 在弱对比屏幕上直接不可读 |

### 9.2 内容与文案

| ❌ 不要 | 改成 |
| --- | --- |
| Emoji 当图标（🚀 ✨ 🎯）| 文字，或单色线性图标 |
| 用 Emoji 组织段落（"📌 要点"）| 小标题 |
| 「赋能」「闭环」「一站式」 | 说具体做了什么 |
| 「正在为您智能分析…」 | 「正在分析回答内容」 |
| 「暂无数据」 | 说明为什么空、怎么让它不空 |
| 感叹号结尾的鼓励语 | 陈述事实 |

**中文文案的三条规则：**

1. **不用"您"，用"你"。** 面试助手不该像客服。
2. **动词开头。** "上传资料"而不是"资料上传功能"。
3. **能写具体数字就写。** "通常十几秒到半分钟，最慢约一分钟"
   比"需要一定时间"有用得多。

### 9.3 形状与装饰

| ❌ 不要 | 为什么 |
| --- | --- |
| 16px 以上的大圆角 | 最容易被识别的"AI 味"特征 |
| 卡片套卡片 | 层次混乱；用背景色分层 |
| 每个元素都加阴影 | 界面会"飘"，且显得廉价 |
| 装饰性色块 / 几何图形 | 不承载信息就是噪音 |
| 三张等宽卡片并排 | 营销页排版，不是工具 |
| 一切居中 | 见 §4.3 |
| 12 种以上的字号 | 说明没有阶梯 |

### 9.4 交互

| ❌ 不要 | 为什么 |
| --- | --- |
| 悬停时元素放大 | 会让相邻元素位移 |
| 装饰性动画 | 见 §7.1 |
| 假的进度百分比 | 见 §7.3 |
| 无限滚动 | 面试历史需要能定位到具体的某一场 |
| 无确认的破坏性操作 | 资料删除需二次确认 |

## 10. 可访问性

**这些不是"加分项"，是功能正确性的一部分。**

### 10.1 对比度

正文与背景至少 **4.5:1**，大字号至少 3:1。

当前令牌已满足，但**新增颜色必须实测**。
`--text-faint`（#9aa1ad）在 `--bg`（#f5f6f8）上约为 2.8:1 ——
**它只能用于装饰性元信息，不能用于需要读清的内容。**

### 10.2 焦点可见

```css
:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}

/* 深色区（顶栏、登录页）上的焦点轮廓用白色 */
```

**不要 `outline: none`。** 键盘用户会完全失去位置感。

### 10.3 语义标签

- 状态区用 `role="status"` + `aria-live="polite"`
  （等待提示已这么做 —— 屏幕阅读器需要被告知"开始了"）
- 表单控件必须有 `<label for>`
- 图标按钮必须有 `aria-label`

### 10.4 不只靠颜色传达

状态同时用**颜色 + 文字**。例如资料状态是
"已索引 · 可检索"这样的文字标签，不是一个小绿点。

色盲用户占男性约 8%，纯颜色编码对他们等于没有编码。

## 11. 组件规范

### 11.1 按钮

| 类型 | 用途 | 样式 |
| --- | --- | --- |
| `btn-primary` | **每屏最多一个** | 实心 `--primary` |
| `btn-ghost` | 次要动作 | 透明底 + 边框 |
| `btn-danger` | 破坏性动作 | 实心 `--danger` |

**"每屏最多一个 primary"是硬规则。** 两个主要按钮等于没有主要按钮。

**等待中的按钮**：保留文字、加转圈、禁用。
不要只留转圈 —— 用户会忘记自己点了什么。

### 11.2 卡片

- 背景 `--surface`，边框 `--border`，圆角 `--radius`
- **不加阴影**（阴影留给浮层）
- 内边距统一 `--sp-4`（16px）

### 11.3 标签（tag）

用于**状态**，不是用于分类。胶囊形，配 `-soft` 底色：

```html
<span class="tag tag-primary">进行中</span>
<span class="tag tag-ok">已索引 · 可检索</span>
<span class="tag tag-warn">索引失败</span>
```

### 11.4 空状态 / 错误

居中，宽度约束在 `--w-read` 内，包含**一个**行动按钮。

### 11.5 页面状态区（`PageState`）

`components/PageState.vue` 统一"错误提示 + 加载占位"。
它承接的是**实测确认的逐字重复**（6 个页面里完全相同的那两段），
不是"看起来像"。

**接口是纯展示的**：它**不接收 `loading` 属性**，
条件由父级的分支控制：

```vue
<template v-if="loading">
  <PageState :error="error" />
</template>
<template v-else-if="session"> … </template>
```

#### ⚠️ 两条实测踩出来的约束

**① 分支条件必须留在原生元素或 `<template>` 上，不能挂在组件上。**

第一版让 `PageState` 自己判断 `v-if="loading"`，结果
**弄断了各页面的 `v-if/v-else-if` 链**：

```vue
<PageState :loading="loading" />   <!-- v-if 在这里 -->
<template v-else-if="session">     <!-- 链断了 -->
```

Vue 靠这条链把 `session` 从 `T | null` **收窄**成 `T`。
链一断，所有 `session.xxx` 都报
`TS18047: 'session' is possibly 'null'` —— 实测 6 个页面十几处。

（`v-if` 挂在组件上其实仍能收窄；坏的是把**原来的 `v-if`
移进组件**，导致兄弟元素上出现没有条件的 `v-else-if`。）

**② 历史页的列表分支链要单独看。**

它的 `v-else-if="!items.length"`（空态）原本挂在
`v-if="loading"` 上。把那个 `v-if` 换掉后，空态**失去条件** ——
那会让空态与列表**同时渲染**，而类型检查先一步报错抓到了它。

因此历史页保留原生 `v-if="error"` 作为链头：
**分支条件不交给组件。**

**③ "组件不判断条件" ≠ "组件无条件渲染全部内容"。**

修 ① 之后加载卡片变成无条件渲染，而**登录页没有 `loading` 状态**
（它只需要错误提示）。结果登录表单里永远挂着一张"正在加载…"，
看起来像卡死了 —— **由用户截图发现，我的两个自动检查都没抓到**。

因此组件有 `show-loading`（默认 `true`）：

```vue
<!-- 有加载态的页面：包在分支里，默认值够用 -->
<template v-if="loading"><PageState :error="error" /></template>

<!-- 没有加载态的页面：明确关掉 -->
<PageState :error="error" :show-loading="false" />
```

**判据是"这个页面有没有加载态"，而那只有调用方知道** ——
所以它该由调用方给，而不是让组件猜。

> ⚠️ **为什么两个自动检查都没抓到它**
>
> - `ui_walkthrough` 只看它**断言过的**元素（历史页行数、
>   资料页 accept 属性、暂停恢复），不看"页面上出现了
>   不该出现的东西"
> - `check_computed_fonts` 只看字号，不看内容
>
> 教训：**"没有失败"不等于"看起来对"。**
> 自动检查覆盖的是它被写去覆盖的东西，而新出现的错误内容
> 属于**覆盖盲区**。因此真实使用仍不可替代 ——
> 这与 D58（只有看截图才发现）是同一类问题。
